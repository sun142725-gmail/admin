## BaseDatePicker 日期选择器修复

用户反馈"时间没法选择"，排查发现 Vant 4 的 van-date-picker 默认 `showToolbar: true`，内置了标题+确认+取消工具栏。
原 BaseDatePicker 在 van-date-picker 之上又手动拼了一层自定义 toolbar，导致双重工具栏叠加，自定义"确认"读取的是过期的 pickerValue 而非 picker 内部实际选中值。

### 修复方案
- 删除自定义 toolbar HTML 和 CSS
- 直接使用 van-date-picker 的 `@confirm` 事件（参数 `{ selectedValues }`）获取实际选中值
- 使用 `@cancel` 事件关闭弹窗
- `title` prop 直接传给 van-date-picker（内置工具栏标题）
- 弹窗打开同步值时加 `nextTick` 确保 picker 已渲染
- SelfDrawer(BaseScroll) 内部 touch-action:none 不影响 popup（teleport=body 在外层）

## BaseRadio 修复：shared 目录 Vant 组件必须显式 import

用户反馈 BaseRadio 渲染后没有显示 radio 项。
**根因**：`src/shared/components/` 目录下的 .vue 文件不在 `unplugin-vue-components` + `VantResolver` 的扫描范围内（plugin 扫描基于 appDir root），所以 BaseRadio.vue 中的 `<van-radio-group>` 和 `<van-radio>` 不会被自动注入 import 语句。运行时 Vue 找不到这些组件定义，radio 不渲染但模板其余部分正常。

**修复**：在 BaseRadio.vue 中显式 import：
```javascript
import VanRadioGroup from 'vant/es/radio-group'
import VanRadio from 'vant/es/radio'
```
模板中使用 `<VanRadioGroup>` / `<VanRadio>`（匹配 import 名）。

**结论（重要规则）**：所有放入 `src/shared/components/` 的封装组件，若内部使用 Vant 组件，**必须显式 import**。这是 shared 目录的硬性约定。
