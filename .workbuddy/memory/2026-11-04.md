## 左侧菜单「同一目录图标要么都有、要么都没有」

- 根因：菜单树来自后端 `GET /resources/tree`（resources 表，seed.service.ts 幂等写入 + deploy-panel/scripts/online 增量 SQL），实体/DTO 无 icon 列；图标 100% 由前端 `MainLayout.tsx` 两张硬编码 Map 决定。后加的 `/stock/strategy`、`/flow`、`/flow/runs`、`/flow/novel`、`/graphic`、`/prompts` 及一级目录「AI 制片厂」未登记，导致股市组 3 有 1 无、AI 制片厂组 1 有 5 无，antd inline 菜单文字缩进参差。
- 方案：新增 `frontend/src/layouts/menuConfig.ts`（纯 TS、无 JSX），把图标映射改为 `MENU_ICON_KEY` 白名单 + `PATH_ICON_KEYS` / `NAME_ICON_KEYS`，`getMenuIconKey` 按 path → name 兜底；`alignSiblingIconKeys` 保证同级一致性（整组无图标则全无；组内有图标则缺失项补 `DEFAULT_ICON_KEY = appstore`）；`buildMenuTree` 先按权限过滤可见项再逐层对齐，避免隐藏菜单影响对齐。
- `MainLayout.tsx` 改为 `buildMenuTree` + `toAntdItems`，`ICON_COMPONENTS: Record<MenuIconKey, ReactNode>` 由 tsc 强制每个 icon key 都有组件；补齐 6 个 path、AI 制片厂及旧名（AI 管理/股市圆桌/任务流）兼容映射。
- 以后新增菜单页：要么在 `PATH_ICON_KEYS` 登记图标 key（并同步 `MENU_ICON_KEY` + `ICON_COMPONENTS`，tsc 会拦），要么整组都不登记 —— 由纯函数兜底，不会再出现混排。
- 测试 `menuConfig.test.ts` 21 项（含真实菜单树每层不混排的不变量断言、权限过滤、折叠态）；全量 `npm test` 27 文件 / 268 测试全绿，`npm run check`（tsc + check-imports）通过。
- 构建：`npm run build` 的 tsc/导入检查阶段通过，vite 清空 `dist/assets` 时被 WorkBuddy safe-delete 守卫拦截（单轮删除 51 > 阈值 50，`SAFE_DELETE_BULK_CONFIRM_REQUIRED`），与代码无关；改用 `vite build --outDir /tmp/rbac-frontend-verify-20261104 --emptyOutDir` 完整构建成功（4224 modules，✓ built in 7.54s）。后续如再遇到，用独立 outDir 验证即可，不要手工删 dist。
