# AI 管理模块 · 产品需求文档（PRD）

- 状态：待评审
- 作者：与 u1s1 协作整理
- 关联：`ai_module_design.md`（技术设计）、`divination_redesign.md`（既有 AI 调用方）

## 1. 背景与目标

当前项目对 AI 的使用只有一处：占卜模块内置 DeepSeek 解卦（硬编码在 `ai.service.ts`，密钥走环境变量，prompt 写死）。随着后续接入更多模型/智能体（含 Dify 应用），需要一个统一的 AI 管理模块，做到：

1. **渠道统一接入**：不同厂商/协议（OpenAI 兼容、Dify、Ollama 等）在一个地方配置，新增模型不改代码
2. **模型统一注册**：同一模型可由多个渠道提供服务（互为备份/分流），按模型名唯一去重
3. **智能体可运营**：提示词、参数、绑定模型在管理端可调整，不必发版
4. **对话即产品**：管理端直接选智能体/模型聊天（含生图），C 端 Vue 后续直接复用接口

## 2. 市场参考与取舍

参考产品：**OneAPI/NewAPI**（渠道-模型映射、密钥托管、负载均衡）、**Dify**（应用编排、提示词工程）、**OpenWebUI / LobeChat**（模型注册表、会话式对话、生图工作台）。

| 借鉴 | 采纳 | 不采纳（本期） |
|---|---|---|
| OneAPI 渠道模型 | 渠道表 + 模型表 + 渠道映射表，优先级/权重分流，连通性测试 | 令牌分发、计费扣费、多租户 |
| Dify 应用即智能体 | Dify 应用作为一种"智能体数据源"，对话路由到 Dify API | 工作流编排、知识库管理（平台自身做 RAG） |
| OpenWebUI 工作区 | 智能体=提示词+参数+模型 的运营实体；对话页选智能体 | 插件/工具市场、多人共享会话 |
| LobeChat 会话 | 多会话管理、流式输出、停止/重新生成 | 语音、数字人、话题自动命名（P2 再说） |

## 3. 用户与场景

| 角色 | 场景 |
|---|---|
| 管理员 | 配置渠道与密钥；探测并注册模型；调优智能体提示词；查看用量日志 |
| 普通登录用户 | 选智能体聊天、文生图、查看自己的历史会话 |
| C 端用户（预留） | 通过同一套 OpenAPI 对话/生图（Vue 端复用，P1） |

## 4. 功能需求

### 4.1 渠道管理（模型配置）`P0`

- 渠道字段：名称、协议类型（`openai-compatible` / `dify` / `ollama`）、BaseURL、API Key（**落库加密**）、优先级、权重、备注、启停
- **连通性测试**：保存前一键测试（chat 用 `GET /models` 或 1-token 对话探测；dify 用应用参数接口）
- **模型探测**：openai-compatible 渠道一键拉取 `/models` 列表，勾选后进入"待注册模型"
- API Key 全程脱敏显示（`sk-****last4`），编辑时不回传明文

### 4.2 模型管理 `P0`

- **模型唯一键 `model_key` 全局唯一**（如 `deepseek-chat`）：不同渠道配同一模型 → 同一条模型记录挂多个渠道映射，而非重复注册（去重规则按用户要求）
- 字段：model_key、显示名、能力标签（`chat` / `image` / `vision` / `embedding`，多选）、上下文长度、最大输出、默认参数、状态
- **模型-渠道映射**：一个模型挂 N 个渠道，每个映射可覆盖上游真实模型名（如渠道侧叫 `deepseek-chat-v3`），设置优先级/权重；调用时按 优先级 → 同级权重随机 路由，失败自动切下一渠道
- 渠道被停用时其映射自动失效

### 4.3 智能体管理 `P0`

- 字段：名称、头像（可空）、描述、**类型**（`native` 内置编排 / `dify` 远程应用）、绑定模型（native 必填）、**系统提示词**（大文本编辑器）、参数（temperature / top_p / max_tokens）、开场白、能力开关（允许生图等）、启停、排序
- dify 类型：选择 Dify 渠道 + 填应用 API 与输入参数映射，提示词在 Dify 侧维护
- 知识调整：P0 以提示词承载领域知识；结构化知识库（RAG）列 P2

### 4.4 AI 对话 `P0`

- 左侧会话列表（多会话、改标题、删除），右侧聊天区
- 每条消息可选：某个**智能体**（用其提示词与模型）或**裸模型**（无系统提示词直接聊）
- SSE 流式输出、打字机效果、**停止生成**、**重新生成**
- 上下文：携带同会话历史（简版按条数+长度截断，P1 换 token 计量）
- vision 模型支持传图理解（P1）
- 智能体开启生图能力时，聊天内可触发生图（P1，先用独立生图页满足）

### 4.5 生图 `P0`

- 文生图表单：提示词、反向提示词（支持则传）、尺寸（预设档位）、数量（1~4）
- 走模型能力标签 `image` 的渠道（OpenAI images 协议优先，其他协议经适配器转换）
- 生成结果落 `files` 文件服务，页面内保存历史（本人可见）

### 4.6 用量与日志 `P1`

- 每次调用记录：用户、模型、渠道、类型（chat/image）、tokens（prompt/completion/total）、延迟、成败与错误摘要
- 管理端列表 + 按模型/用户/日的简版统计卡片；不做计费

### 4.7 权限 `P0`

- 新菜单「AI 管理」：渠道与模型（管理）、智能体管理、AI 对话（所有登录用户）、生图（所有登录用户）
- 权限码：`ai:provider:manage`、`ai:model:manage`、`ai:agent:manage`、`ai:usage:view`；对话/生图登录即可，管理类码绑定超管角色
- C 端复用：接口按 JWT 鉴权，P1 直接给 Vue 用

## 5. 非功能需求

- **密钥安全**：渠道 API Key AES 加密落库（独立环境变量 `AI_ENCRYPTION_KEY`），接口永不回传明文
- **流式体验**：对话/生图进度走 SSE，事件契约沿用占卜模块的 `chunk / done / error`
- **稳定性**：单次流式总超时（默认 120s）、渠道失败转移、错误信息脱敏（不透出上游 key/URL）
- **审计**：渠道/模型/智能体的增删改走现有审计中心
- **限流**：对话与生图接口接入现有全局限流，生图按用户加每分钟次数上限

## 6. 阶段规划

| 阶段 | 内容 | 出口标准 |
|---|---|---|
| P0（MVP） | 渠道/模型/映射/智能体四个管理页 + AI 对话（流式多会话）+ 文生图 + 权限 + 用量日志表 | 用 DeepSeek 配一条渠道，从对话页流式聊通；同模型双渠道可切换 |
| P1 | Dify 智能体接入、vision 传图、聊天内生图、用量统计页、C 端 Vue 复用、token 计量截断 | Dify 应用可被选为智能体聊天 |
| P2 | 知识库 RAG、工具/插件、话题自动命名、计费配额 | 视需求 |

## 7. 已确认决策（原开放问题）

1. 生图 P0 只接 OpenAI images 协议（含兼容网关）；豆包/即梦等原生协议放 P1
2. 会话标题 P0 取首条消息前 20 字，**支持手动编辑**
3. Dify P1 只接 chat/agent 型应用；渠道探测发现工作流型时提示不支持
